Secure AI Development: Architecting the Pi.dev HarnessThe deployment of Large Language Models (LLMs) as autonomous coding assistants requires a fundamental shift in how we manage context, execution, and security. While many agentic frameworks ship with black-box defaults, Pi.dev (Pi) takes the opposite approach. Written in Rust and TypeScript, Pi is an aggressively minimalist, unopinionated terminal harness. It ships with absolutely no built-in sub-agents, no native permission popups, no background bash execution, and no native Model Context Protocol (MCP) support.Instead, Pi forces the developer to explicitly engineer their own boundaries and workflows. It acts as a blank slate that must be extended via a robust TypeScript Extensions API, modular Markdown Skills, and persistent context configurations. This report outlines the definitive architecture for building a secure, high-performance development agent on Pi, integrating Defense-in-Depth security, E2B compute isolation, and advanced token optimization.1. The Repository and Agent ArchitectureBuilding a secure Pi agent begins with the structural layout of the project workspace. Because Pi dynamically discovers its capabilities based on directory structures, establishing a strict hierarchy is the first line of defense and context management.The Project StructureA production-grade Pi architecture should look like this:my-secure-project/
├── AGENTS.md                 # The core constitution and routing logic
├── SECURITY.md               # Immutable security boundaries
├──.env.schema               # Varlock environment definitions (no secrets)
├──.gitignore                # Must allow!.env.schema
│
├──.pi/                      # Project-local Pi configuration 
│   ├── settings.json         # Extension paths, MCP routing, and tool overrides
│   ├── extensions/           # TypeScript security hooks and tool modifiers 
│   │   ├── guardrails.ts     # Implementation of tool_call interceptions
│   │   └── e2b-compute.ts    # E2B execution routing 
│   ├── skills/               # Domain-specific Markdown playbooks 
│   │   ├── security-review/  # SAST and secret auditing workflows
│   │   └── deployment/       # CI/CD trigger procedures
│   └── prompts/              # Custom prompt templates
│
└── src/                      # Application source codeContext Anchoring: AGENTS.mdThe AGENTS.md file serves as the agent's persistent root context. Unlike traditional documentation that an agent might forget, this file is injected directly into the system prompt. To prevent "Context Bloat," AGENTS.md must be kept extremely lean. It should not contain exhaustive API documentation; instead, it should define project conventions, required testing commands, and pointers to available Skills.2. On-Demand Intelligence: Skills over MapsA common anti-pattern in agentic development is flooding the context window with massive repository maps or monolithic architectural guidelines. Pi solves this via Skills.Skills are self-contained, on-demand capability packages. Stored in .pi/skills/<skill-name>/SKILL.md, they act as precise playbooks for specific tasks. Instead of the agent holding all deployment instructions in memory constantly, it can invoke the deployment skill only when asked to deploy.Why Skills over Static Maps:Token Efficiency: A skill's body loads into the context window only when it is explicitly invoked (e.g., via the /skill:name command) or when the agent autonomously determines it is relevant based on the skill's description.Tool Gating: Skills can define an allowed-tools parameter, temporarily granting or restricting bash capabilities for the duration of that specific workflow.Procedural Rigor: Skills enforce Standard Operating Procedures (SOPs). For example, a security-review skill can mandate that the agent runs Semgrep and TruffleHog before proposing a fix.3. The Security Layer: Extensions and HooksBecause Pi has no native permission popups, running it blindly on a host machine allows the agent to execute destructive commands (e.g., rm -rf) or read sensitive credentials. Protection is achieved through Pi's TypeScript Extensions API, which uses jiti to load modules on the fly.Intercepting the tool_call EventThe cornerstone of Pi's security is the tool_call lifecycle hook. Before any tool (like bash or read) reaches the operating system, an extension can intercept the payload.By deploying packages like @aliou/pi-guardrails in the .pi/extensions/ folder, security engineers can enforce strict boundaries.Destructive Command Blocking: The extension evaluates the bash tool payload. If the command contains dangerous patterns, it utilizes ctx.ui.confirm() to present a blocking Terminal User Interface (TUI) overlay. If the developer denies the action, the hook returns { block: true, reason: "Blocked by user" }, preventing execution.Path Protection: Extensions can evaluate read and edit tool calls, returning immediate blocks if the agent attempts to access .env files, .aws/credentials, or SSH keys.4. Compute to Pi: E2B SandboxingEven with robust guardrails, executing non-deterministic LLM output on a local machine is a fundamental security risk. The architecture mandates the integration of E2B cloud sandboxes.There are two primary methods to connect Pi to E2B compute:Remote Execution Extension (pi-extension-e2b): A custom Pi extension can intercept all bash tool executions via the tool_call hook and route the payload to a remote E2B Firecracker microVM. The code executes in the sub-200ms cloud environment, and only the standard output is returned to the Pi harness.Containerized Harness: Alternatively, the entire Pi CLI process can be run directly inside an E2B container using the E2B SDK (e.g., e2b sbx create). In this setup, the agent operates natively, but its "world" is strictly confined to the ephemeral cloud instance.5. Integrating the Defense-in-Depth MCP StackTo integrate external security tools and RAG systems, Pi requires the pi-mcp-adapter extension, as it does not support MCP natively. Once installed, the following tools complete the security stack:Layer 1: Secret Management (Varlock)To prevent the agent from accidentally ingesting plain-text secrets, the project uses Varlock.The agent reads the .env.schema file to understand the required variables and their formats.A custom Pi extension or a specific Skill instructs the agent that it must run varlock load for validation, preventing it from ever executing cat.env. Real secrets are injected only at execution time via varlock run.Layer 2: Auditing and Code Security (Snyk & TruffleHog)Snyk Studio MCP: Connected via the adapter, this provides the agent with the snyk_code_scan (SAST) and snyk_sca_scan (Dependency) tools. A Pi Hook on the tool_result of an edit command can force the agent to trigger these scans automatically.TruffleHog: Deployed via an MCP server, TruffleHog allows the agent to run active, verified secret detection (e.g., trufflehog git file://.) across the repository history to ensure no hallucinated keys are committed.Layer 3: Verified RAG (Context7)To combat API hallucination, the Context7 MCP server provides the resolve-library-id and query-docs tools. This allows the Pi agent to fetch up-to-date, version-specific documentation directly into its context. (Note: Organizations must implement strict internal Prompt Injection guardrails to mitigate the risk of "ContextCrush" supply-chain attacks originating from poisoned external documentation registries ).6. Token Optimization: RTK and SophonA persistent issue with terminal agents is the "shell firehose"—raw, verbose logs from test runners and package managers that consume massive amounts of the context window. To optimize this within the Pi architecture, two distinct tools are utilized:RTK (Rust Token Killer):
RTK operates entirely outside of Pi at the OS shell level. By wrapping commands (e.g., configuring Pi to run rtk cargo test instead of cargo test), RTK intercepts the raw output, deduplicates errors, strips ANSI codes, and truncates success messages. This reduces Pi's token consumption by 60% to 90% without requiring any changes to the agent's internal logic.Sophon MCP:While RTK handles shell output, the Sophon MCP server operates at the memory and file-read level. Achieving up to 94% output compression with zero LLM overhead, Sophon provides query-aware section filtering for structured prompts and context summarization, drastically reducing the token footprint of Pi's file operations and historical memory retention.ConclusionPi.dev is a powerful, unopinionated execution engine that demands rigorous architectural planning. By leveraging its TypeScript extensions for strict tool_call guardrails, migrating heavy domain knowledge into modular Skills, isolating compute within E2B sandboxes, and utilizing the pi-mcp-adapter to connect to enterprise security scanners (Varlock, Snyk, TruffleHog), development teams can forge an AI workflow that is exceptionally fast, highly optimized via RTK and Sophon, and secure by design.
